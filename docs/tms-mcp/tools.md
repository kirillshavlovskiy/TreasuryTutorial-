## How to read this file

1. **Being listed here does not mean your session can see or call it.** `app/src/mcp/server.ts`
   registers a tool for a given caller only if that caller's `ResourcePermissions` satisfy
   `requiredPermissions`. This file, when built from a `treasury` checkout, is not limited by any
   one session's permissions — it can (and normally does) list tools a narrower-permission session
   cannot see. The reverse also holds: a tool your session sees that isn't listed here yet is
   genuinely new to this catalogue and worth syncing (`/fx-sync-mcp-tools`) — but a tool listed
   here that your session doesn't currently see is expected, not evidence it was removed. See
   `.claude/rules/project/tms-mcp.md` § "Session start" for exactly what that means for keeping
   this file current.
2. **This reflects the dev server (`treasury.deel.training`), not production.** A tool can be
   merged to `dev` and registered here before it is deployed to prod, or vice versa if a hotfix
   ships to prod first.
3. **Every tool also accepts `fields` (allowlist) and `omit` (denylist) response-projection
   parameters**, injected uniformly by `mergeToolInputSchema` — they are not repeated in every
   tool's own parameter table below. Use them to trim a large response instead of re-reading it.
4. **A mutating tool never has its own description or parameter table anywhere in this file** —
   not in "Mutating tools" below (name and required permission only), not in "Deep reference"
   (filtered to read-only tools only). This project only calls read-only tools
   (`.claude/rules/project/tms-mcp.md`) — see "Hard rules" in `docs/tms-mcp/CLAUDE.md`.
   **This is narrower than "no mention at all"**: a read-only tool's *own* description can still
   name a mutating tool's parameter in passing — e.g. `list_financial_institutions`'s description
   says to use it "to resolve `financialInstitutionId` for tms_create_financial_account". That
   text is inherited verbatim from the read-only tool's own upstream documentation, not added by
   this catalogue, and it names an identifier to look up, not how to construct the mutating call.
5. **A tool name the catalogue has never classified goes in "Unclassified — verify before
   calling"** (see `.claude/skills/fx-sync-mcp-tools/SKILL.md` Step 3) — this section is present
   in the file only when it is non-empty. No section below this heading right now means every
   tool this sync could see was classified, not that the mechanism is unused.

## Deep reference

Full parameter tables for the domains this project actually uses: FX Trading, Accounts, Notional Pool, Balances, Meta, Investments. **Read-only tools only** — a mutating tool in one of these domains (e.g. `tms_create_financial_account`, `edit_financial_account`) is named in "Mutating tools — never call" above and deliberately has no entry here. [letsdeel/treasury#14082](https://github.com/letsdeel/treasury/pull/14082) added 10 of the tools below (see the header note at the top of this file for which) — merged and confirmed live as of 2026-09-03; they are no longer tagged PENDING.

### FX Trading

#### `fx_hedging_controls`

List auto-hedging control rules: which currency pairs are auto-hedged, enabled/disabled status, channel (FXALL/CITI/JPMORGAN), tenor, netting settings, thresholds, source of exposure filters, payment provider filters.

Permission: `fx_orders: 'READ'`

| Param | Type | Required | Description |
|---|---|---|---|
| `baseCurrency` | string | no | Base currency code (e.g. EUR) |
| `quoteCurrency` | string | no | Quote currency code (e.g. USD) |
| `autoHedgingEnabled` | boolean | no | Filter by enabled/disabled |
| `product` | enum | no | Product filter (EOR, CONTRACTOR, GP) |
| `sourceOfExposure` | enum | no | Source of exposure filter |
| `limit` | number | no | Max rows (default 50, max 1000) |

#### `fx_order_blotter_search`
