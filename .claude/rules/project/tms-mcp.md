# TMS Finance MCP — read-only only, kept in sync

> Maintained by: all team members
> Hard project rule. Full catalogue and task-to-tool map: `docs/tms-mcp/CLAUDE.md` and `docs/tms-mcp/tools.md`.

## Rule

**Only call TMS Finance MCP tools with `annotations.readOnlyHint: true`.** This project reads
Treasury data for analysis; it never books, creates, edits, or deletes anything there. Both the
generated catalogue (`docs/tms-mcp/tools.md`) and its "Deep reference" section only carry
descriptions and parameters for read-only tools — a mutating tool never gets its own description
or parameter table anywhere in the catalogue, only a name and required permission. (A read-only
tool's *own* description can still name a mutating tool's parameter in passing — e.g.
`list_currencies` says to use it "to resolve `currencyId` for tms_create_financial_account". That
text is inherited from the read-only tool's own upstream documentation; it names an identifier to
look up, not how to construct the mutating call.)

## Session start — check for a tool the catalogue doesn't have yet

At the start of a session where the TMS Finance MCP is connected, before relying on
`docs/tms-mcp/tools.md`: check whether any TMS MCP tool name visible in **this** session is
**missing from** the catalogue's "Tool name index".

- **Every session-visible name is already in the index:** say nothing, proceed normally. This is
  the common case even when the index has MORE names than this session can see — see the note
  below, that is expected and not a problem.
- **A session-visible name is missing from the index:** run `/fx-sync-mcp-tools` (incremental — it
  only adds what's missing, never deletes), then mention in one line what was added.
- **Sync fails:** say so, keep working, and treat the catalogue as possibly stale for this
  session rather than blocking the task on it.

**The comparison is one-directional. Do not treat "index has a name this session can't see" as a
problem, and never as grounds to remove it.** `app/src/mcp/server.ts` registers a tool for a
caller only if that caller's `ResourcePermissions` satisfy it, so a session with narrower
permissions than whoever last ran `--full` against a `treasury` checkout will routinely see fewer
names than the index — that gap is expected, is usually the mutating tools (which need broader
grants than most read-only ones), and is exactly the case `docs/tms-mcp/tools.md` § "How to read
this file" item 1 documents. Only a name **this session sees that the index does not have** is a
real signal — a tool this project genuinely hasn't catalogued yet.

A `SessionStart` hook (`.claude/settings.json` → `hooks.SessionStart`) prints the catalogue's age
and tool count into context automatically — it cannot see the live tool list itself (a hook is a
shell command, not a model), so it cannot do this comparison on its own. The check above is what
actually catches a missing tool; the hook only tells you the catalogue exists and how old it is.

**Honest gaps:**
- The hook only reports staleness, never a real diff — the model doing the one-directional
  comparison above is what actually finds a missing tool, and it can be skipped.
- This only runs in a session where the TMS Finance MCP is connected at all.
- Without a `treasury` checkout, the index can only ever grow by what some session has actually
  seen — a tool that exists in TMS but that no session with the right permissions has ever synced
  stays absent indefinitely. A `treasury` checkout (`/fx-sync-mcp-tools --full`) is the only way
  to populate the full registered set independent of any one session's permissions.

## Forbidden

- Calling any tool without first confirming (via `docs/tms-mcp/tools.md`) that it is read-only.
- Treating an unclassified tool name (one the catalogue has never seen, with no local `treasury`
  checkout available to check `annotations.readOnlyHint`) as read-only by default — see the
  "Honest gap" section in `docs/tms-mcp/CLAUDE.md`.
- Logging a tool's response payload — account identifiers, balances, counterparty data are
  RESTRICTED.
- Using a rate without its `date` and `provider` in anything that gets stored or compared.
- Hand-editing `docs/tms-mcp/tools.md` — it is generated by `/fx-sync-mcp-tools`.

## Allowed

- Any tool listed under "Read-only catalogue by domain" in `docs/tms-mcp/tools.md`.
- Running `/fx-sync-mcp-tools` any time the catalogue looks stale, not just at session start.
